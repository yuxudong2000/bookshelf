## 1. 需求概述

### 用户/业务目标

为用户提供一个在线化的个人书架管理工具，让用户可以集中展示自己拥有的书籍，并按类型对书籍进行分组浏览，从而快速定位和管理个人藏书。

### 解决的问题

- 书籍分散在不同地方（实体书架、电子阅读器、购物记录等），无法一目了然地掌握全貌
- 缺少按类型归类的能力，查找某一类书籍时需要逐一翻找
- 个人藏书信息没有数字化的集中管理入口

## 2. 功能范围

### 本次做什么（MVP 范围）

- F01：书架总览 — 展示用户所有书籍的列表
- F02：书籍添加 — 支持新增书籍到书架
- F03：类型分组 — 支持按书籍类型分组查看
- F04：书籍详情 — 查看单本书籍的完整信息
- F05：书籍删除 — 从书架中移除书籍

### 本次不做什么

- 用户认证与多用户隔离（MVP 阶段假设单用户场景）
- 书籍封面上传
- 书籍借阅状态管理
- 书籍评分与评论
- 书架主题/皮肤定制
- 数据导入/导出
- 移动端原生适配（响应式 Web 即可）

## 3. 验收标准

### 功能点 F01：书架总览

**用户故事**：作为书架主人，我希望打开页面就能看到我所有的书籍，这样我可以快速了解我的藏书全貌。

验收标准：

- F01-AC01：Given 书架中有书籍 When 用户访问书架首页 Then 显示所有书籍的列表（UI E2E）
- F01-AC02：Given 书架为空 When 用户访问书架首页 Then 显示空态提示「书架空空如也，快去添加第一本书吧」（UI E2E）
- F01-AC03：Given 书架中有 N 本书 When 书架列表加载 Then 每本书至少展示书名、类型标签和作者（UI E2E）
- F01-AC04：Given 书架列表正在加载 When 数据未返回 Then 显示加载态指示器（UI E2E）
- F01-AC05：Given 书架中有书籍 When 前端请求书架列表 API Then 后端返回书籍数组且每条记录包含 id、书名、类型、作者字段（黑盒 API）

### 功能点 F02：书籍添加

**用户故事**：作为书架主人，我希望向书架添加新的书籍，这样我可以持续记录我的藏书。

验收标准：

- F02-AC01：Given 用户在书架页面 When 点击添加按钮 Then 弹出添加书籍的表单/弹窗，包含书名（必填）、类型（必填）、作者（必填）、简介（选填）四个字段（UI E2E）
- F02-AC02：Given 添加表单已打开 When 用户填写书名、类型和作者并提交 Then 书籍成功添加到书架列表中（UI E2E + 黑盒 API）
- F02-AC03：Given 添加表单已打开 When 用户未填写书名就提交 Then 表单提示「书名不能为空」并阻止提交（UI E2E）
- F02-AC04：Given 添加表单已打开 When 用户未填写作者就提交 Then 表单提示「作者不能为空」并阻止提交（UI E2E）
- F02-AC05：Given 用户提交了添加请求 When 后端 API 处理成功（返回 200） Then 书架列表实时刷新并包含新书（UI E2E + 黑盒 API）
- F02-AC06：Given 用户提交了添加请求 When 后端 API 处理失败（返回非 200） Then 显示错误提示「添加失败，请重试」（UI E2E）

### 功能点 F03：类型分组

**用户故事**：作为书架主人，我希望按类型分组查看书籍，这样我可以快速找到某一类的书。

验收标准：

- F03-AC01：Given 书架中有多种类型的书籍 When 用户切换到分组视图 Then 书籍按类型分组展示，每组显示类型名称和该组书籍（UI E2E）
- F03-AC02：Given 书架中有书籍 When 用户在列表视图和分组视图之间切换 Then 视图正确切换并保持数据一致（UI E2E）
- F03-AC03：Given 分组视图中某类型下无书 When 显示该分组 Then 该分组不显示或显示空组提示（UI E2E）
- F03-AC04：Given 用户添加了一本新类型书 When 切换到分组视图 Then 新类型自动成为一个新分组（UI E2E）
- F03-AC05：Given 书架中有 N 种类型 When 分组视图加载 Then 每个分组标题旁显示该组书籍数量（UI E2E）

### 功能点 F04：书籍详情

**用户故事**：作为书架主人，我希望点击某本书后能看到它的完整信息，这样我可以回忆这本书的细节。

验收标准：

- F04-AC01：Given 书架列表中有书籍 When 用户点击某本书 Then 进入/弹出该书的详情，展示书名、类型、作者（必填）和简介（选填，无则不显示该区域）（UI E2E）
- F04-AC02：Given 书籍详情已展示 When 用户关闭详情 Then 回到之前的书架列表视图（UI E2E）
- F04-AC03：Given 书籍简介为空 When 详情展示 Then 简介区域不显示或显示「暂无简介」，不影响其他必填信息展示（UI E2E）

### 功能点 F05：书籍删除

**用户故事**：作为书架主人，我希望从书架移除不再需要的书籍，这样书架始终反映我当前的藏书。

验收标准：

- F05-AC01：Given 书架中有书籍 When 用户在书籍条目或详情中触发删除操作 Then 弹出确认提示「确定要删除这本书吗？」（UI E2E）
- F05-AC02：Given 删除确认提示已弹出 When 用户确认删除 Then 书籍从书架中移除，列表刷新（UI E2E）
- F05-AC03：Given 删除确认提示已弹出 When 用户取消删除 Then 提示关闭，书籍保留在书架中（UI E2E）
- F05-AC04：Given 用户确认删除 When 后端 API 处理成功 Then 列表不再显示该书；若在分组视图，对应分组数量同步减少（UI E2E + 黑盒 API）
- F05-AC05：Given 用户确认删除 When 后端 API 处理失败 Then 显示错误提示「删除失败，请重试」，书籍保留在列表（UI E2E）

## 5. 风险与依赖

### 技术可行性风险

- 需要后端 API + 数据库支撑数据持久化，涉及前后端联调

### 外部依赖

- 无第三方服务依赖；书籍信息由用户手动录入，不涉及 ISBN 查询等外部接口
- 后端技术栈选型由技术设计阶段确定

### 已确认决策（yuxudong 确认于 2026-09-14）

- **数据持久化方案**：采用后端 API + 数据库，不使用 localStorage
- **书籍类型体系**：自由输入，不使用预设列表
- **书籍字段范围**：书名、类型、作者为必填，简介为选填
