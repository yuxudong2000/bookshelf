## 1. 需求概述

### 用户/业务目标

在现有书架 MVP（书架总览、添加、类型分组、详情、删除）的基础上，增加**用户自定义分组**能力：用户可以创建自己的分组（如「在读」「收藏」「书单A」），并把书架上的书归属到一个或多个分组中展示，从而按照自己的组织方式浏览书籍，而不仅限于按书籍「类型」这一固有属性分组。

### 解决的问题

- MVP 已支持按「类型」自动分组（F03），但类型是书籍的固有属性，无法体现用户个性化的整理诉求（如按阅读状态、按主题书单整理）
- 用户缺少自定义、可维护的分组容器来组织书架，也缺少把书籍加入/移出分组的操作入口
- 缺少「按自定义分组」浏览书架的视图

## 2. 功能范围

### 本次做什么

- F06：分组管理 — 用户可以创建、重命名、删除自定义分组
- F07：书籍分组归属 — 用户可以将某本书加入一个或多个分组，或从分组中移除
- F08：按分组浏览 — 书架支持按自定义分组的视图，展示各分组及其包含的书籍

### 本次不做什么

- 分组的排序自定义（分组展示顺序默认按创建时间）
- 分组的嵌套/层级结构（仅支持单层分组）
- 分组的分享、协作或多用户可见性控制
- 将「类型分组」（F03）与「自定义分组」合并为同一套数据模型或做迁移
- 分组图标、颜色等视觉自定义
- 批量将多本书一次性加入分组的批量操作入口（本次仅支持单本书逐一操作）

## 3. 验收标准

### 功能点 F06：分组管理

**用户故事**：作为书架主人，我希望能创建、重命名、删除自己的分组，这样我可以按自己的方式组织书架。

验收标准：

- F06-AC01：Given 用户在分组管理入口 When 点击「新建分组」并输入分组名称后提交 Then 新分组创建成功并出现在分组列表中（UI E2E + 黑盒 API）
- F06-AC02：Given 新建分组表单已打开 When 用户未填写名称就提交 Then 提示「分组名称不能为空」并阻止提交（UI E2E）
- F06-AC03：Given 已存在名为「X」的分组 When 用户新建同名分组「X」并提交 Then 提示「分组名称已存在」并阻止创建（UI E2E + 黑盒 API）
- F06-AC04：Given 分组列表中有分组 When 用户对某分组执行重命名并提交新名称 Then 分组名称更新，且该分组下的书籍归属关系保持不变（UI E2E + 黑盒 API）
- F06-AC05：Given 分组列表中有分组 When 用户对某分组执行删除并确认 Then 该分组从分组列表中移除，原分组内的书籍本身不被删除，仅解除与该分组的归属关系（UI E2E + 黑盒 API）
- F06-AC06：Given 删除分组的确认提示已弹出 When 用户取消删除 Then 分组保留，归属关系不变（UI E2E）
- F06-AC07：Given 分组列表为空（用户尚未创建任何分组） When 用户查看分组管理入口 Then 显示空态提示「还没有分组，创建一个开始整理书架吧」（UI E2E）

### 功能点 F07：书籍分组归属

**用户故事**：作为书架主人，我希望把某本书加入一个或多个分组，或者把它从分组中移出，这样书籍能反映我当前的整理状态。

验收标准：

- F07-AC01：Given 书籍详情或列表条目中有分组归属入口 When 用户打开该入口 Then 展示当前所有分组及该书已归属的分组勾选状态（UI E2E）
- F07-AC02：Given 分组归属入口已打开 When 用户勾选一个未归属的分组并确认 Then 该书成功加入该分组，分组详情页可见此书（UI E2E + 黑盒 API）
- F07-AC03：Given 某本书已归属分组 A When 用户在归属入口取消勾选分组 A 并确认 Then 该书从分组 A 移除，其他分组归属不受影响（UI E2E + 黑盒 API）
- F07-AC04：Given 某本书同时归属分组 A 和分组 B When 用户查看该书详情 Then 详情页展示该书当前归属的所有分组名称（UI E2E）
- F07-AC05：Given 用户对某本书未勾选任何分组 When 保存归属设置 Then 该书不出现在任何自定义分组视图中，但仍存在于书架总览（UI E2E + 黑盒 API）
- F07-AC06：Given 用户提交分组归属变更 When 后端 API 处理失败 Then 显示错误提示「设置分组失败，请重试」，归属状态回退到变更前（UI E2E）
- F07-AC07：Given 某本书被删除（F05 删除操作） When 删除成功 Then 该书与所有分组的归属关系一并清除（黑盒 API）

### 功能点 F08：按分组浏览

**用户故事**：作为书架主人，我希望切换到「自定义分组」视图，按分组查看书籍，这样我可以专注浏览某一类整理好的书单。

验收标准：

- F08-AC01：Given 用户已创建至少一个分组 When 用户切换到「自定义分组」视图 Then 按分组展示书籍，每组显示分组名称、书籍数量和该组内的书籍（UI E2E）
- F08-AC02：Given 某分组下没有归属任何书籍 When 显示该分组 Then 该分组展示为空组，提示「该分组还没有书」（UI E2E）
- F08-AC03：Given 一本书同时归属多个分组 When 查看「自定义分组」视图 Then 该书在其归属的每个分组中都会出现（UI E2E）
- F08-AC04：Given 用户尚未创建任何分组 When 切换到「自定义分组」视图 Then 显示空态提示「还没有分组，创建一个开始整理书架吧」，并提供创建分组的入口（UI E2E）
- F08-AC05：Given 书架中同时存在「类型分组」（F03）和「自定义分组」视图 When 用户在两种视图间切换 Then 两个视图互不影响、各自正确展示（UI E2E）
- F08-AC06：Given 用户在「自定义分组」视图中删除了某本书 When 删除成功 Then 该书从所有分组视图中同步消失（UI E2E）

## 5. 风险与依赖

### 技术可行性风险

- 需要新增「分组」实体及「书籍-分组」多对多关系的数据模型与迁移，涉及数据库 schema 变更（在现有 `books` 表基础上新增 `groups` 表和关联表）
- 现有 F03 类型分组与本次 F08 自定义分组是两套并行的分组视图，需要在信息架构上明确区分入口，避免用户混淆

### 外部依赖

- 无第三方服务依赖
- 依赖现有书籍数据模型（`server/src/db.ts`、`server/src/routes/books.ts`）作为分组归属关系的关联对象

### 需要 yuxudong 确认的点

- 分组数量是否需要上限（本文档暂不设上限，如有性能或体验考量请明确）
- 一本书是否允许不归属任何分组（本文档验收标准 F07-AC05 默认允许，如需强制归属请告知）
